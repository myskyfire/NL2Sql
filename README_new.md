# DataMind AI - NL2SQL 企业级自然语言数据分析平台

## 📖 项目简介

DataMind AI 是一款基于 **Spring Boot 3.2.5 + LangChain4j 1.12.2** 构建的企业级自然语言数据分析平台。通过集成多种 LLM 提供者（Ollama、ChatGLM、Qwen 等），用户只需用自然语言描述数据需求，系统即可自动生成 SQL、执行查询、并以可视化图表和 AI 总结的形式呈现结果。

### 核心价值

| 特性 | 描述 |
|------|------|
| 🎯 **零门槛交互** | 业务人员无需掌握 SQL，自然语言即可查询 |
| ⚡ **秒级响应** | 平均 3 秒内返回结果，含 LLM 调用时间 |
| 🔒 **企业级安全** | 四层防护体系，保障数据安全 |
| 🤖 **智能洞察** | AI 自动分析数据，提供业务建议 |

## 🤖 ReAct Agent 架构

### 工作原理

ReAct Agent 基于 **ReAct（Reasoning + Acting）** 模式，通过迭代式推理和行动循环实现自然语言到 SQL 的转换。

### 执行流程

```
用户问题
    │
    ▼
┌─────────────────────────────────────────────┐
│  1. 构建消息列表 + 工具定义                   │
│     - System Prompt（核心规则）               │
│     - 历史消息（过滤clarify_datasource）      │
│     - 数据源上下文                           │
│     - 工具定义（OpenAI 格式）                 │
└─────────────────┬───────────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────────┐
│  2. 调用 LLM（generateWithTools）           │
│     - 传递消息列表 + tools 参数               │
│     - LLM 返回结构化 tool_calls              │
└─────────────────┬───────────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────────┐
│  3. 解析 tool_calls                         │
│     - 提取工具名称和参数                     │
│     - 处理 arguments（String/Map兼容）        │
└─────────────────┬───────────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────────┐
│  4. 执行工具（Tool Executor）                │
│     - retrieve_table_schema（表结构检索）      │
│     - generate_sql（SQL生成）                │
│     - execute_sql（SQL执行）                 │
│     - summarize_result（结果总结）            │
│     - generate_chart（图表生成）              │
└─────────────────┬───────────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────────┐
│  5. 添加工具结果到消息历史                   │
│     - role: tool                            │
│     - name: 工具名称                         │
│     - content: 执行结果                      │
└─────────────────┬───────────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────────┐
│  6. 多轮迭代（最多10次）                    │
│     - 继续调用 LLM                          │
│     - 直到 LLM 不再返回 tool_calls           │
└─────────────────┬───────────────────────────┘
                  │
                  ▼
              最终答案
```

### System Prompt 设计

```java
// ReActAgent.buildSystemPrompt()
你是一个智能数据分析助手。

## 核心规则
1. **数据源处理**：
   - 用户消息以 `[数据源ID: XXX]` 开头
   - 如果为 null → 调用 clarify_datasource
   - 如果有数字 → 直接使用该 ID，禁止再次澄清

2. **查询执行**：
   - 数据源明确时，调用 execute_standard_query(question, datasourceId)
   - 该工具自动完成：检索表结构、生成 SQL、评估风险、执行查询
   - 禁止手动调用底层工具

3. **特殊意图**：
   - [INTENT:AI_SUMMARY] → 调用 summarize_result
   - [INTENT:GENERATE_CHART] → 调用 generate_chart

4. **返回规则**：
   - 工具返回结构化数据时，直接返回，不要生成额外回答
   - 禁止输出 thinking/reasoning 内容
```

## 🔧 工具（Tool）系统

### 工具分类

| 类别 | 工具名称 | 功能 |
|------|----------|------|
| **查询执行** | execute_standard_query | 执行完整查询流程 |
| | execute_sql | 直接执行 SQL |
| | execute_safe_sql | 安全模式执行 |
| **表结构** | retrieve_table_schema | 检索表结构 |
| | get_table_metadata | 获取表元数据 |
| | get_table_relationships | 获取表关联关系 |
| **SQL生成** | generate_sql | 生成 SQL |
| | generate_sql_from_schema | 基于表结构生成 |
| | validate_sql | 验证 SQL |
| **风险控制** | analyze_sql_risk | SQL 风险分析 |
| | estimate_cost | 成本估算 |
| **智能功能** | summarize_result | 结果总结 |
| | generate_chart | 图表生成 |
| | rag_enhancer | RAG 增强 |
| **辅助工具** | conversation_memory | 对话记忆 |
| | synonym_expander | 同义词扩展 |

### 统一响应格式

所有工具返回统一格式，便于 LLM 和前端处理：

```json
{
  "success": true | false,
  "type": "data" | "clarification" | "error" | "summary" | "chart",
  "data": { ... },
  "clarification": { ... },
  "error": { ... },
  "metadata": { ... }
}
```

## 📜 技能（Skill）系统

### Skill 架构

Skills 基于 **Groovy 脚本**实现，支持热加载和灵活的业务流程编排。

### 内置 Skills

| Skill | 描述 | 核心逻辑 |
|-------|------|----------|
| **standard-query** | 标准查询技能 | 表结构检索 → SQL 生成 → 风险评估 → 执行 → 返回结果 |
| **sql-validate-execute** | SQL 验证执行 | SQL 验证 → 执行 → 错误处理 |
| **sql-performance-analysis** | SQL 性能分析 | 执行计划分析 → 索引检查 → 成本估算 |
| **report-with-insights** | 报表与洞察 | 标准查询 + AI 总结 + 图表推荐 |
| **simple-data-query** | 简单数据查询 | 直接执行 SQL 并返回结果 |

## 📊 表选择流程

### 多层缓存机制

| 缓存级别 | 命中条件 | 命中率 | TTL |
|----------|----------|--------|-----|
| **L1** | 精确查询匹配 | - | 30 分钟 |
| **L2** | 归一化模板匹配（评分≥4） | - | 30 分钟 |
| **L3** | 语义相似度 > 0.85 | - | 24 小时 |

### 迭代式表发现

```
初始检索（向量检索）
    │
    ▼
┌─────────────────────────────────────┐
│  第1轮 LLM 交互                      │
│  - 提供表结构和关联关系               │
│  - LLM 判断是否需要补充表             │
│  - 如需补充，更新表列表               │
└─────────────────┬───────────────────┘
                  │
                  ▼ (最多3轮)
┌─────────────────────────────────────┐
│  最终表列表                          │
│  - 如果表数量 > 10，让用户选择        │
│  - 否则返回选定表                     │
└─────────────────────────────────────┘
```

### 缓存键设计

```java
// L1: 精确匹配
cacheKey = datasourceId + ":" + query.trim().toLowerCase()

// L2: 归一化模板匹配
normalizedQuery = normalizeQueryForCache(query) // hanlp/regex 实体提取

// L3: 语义相似度
chromaQuery = expandSynonyms(query) // 同义词扩展后检索
```

| 层级 | 防护内容 | 实现方式 |
|------|----------|----------|
| **第一层** | 认证授权 | JWT Token + 白名单 + 角色权限 |

| **第四层** | SQL 验证 | JSqlParser AST 解析 + 危险操作拦截 |

## 🔧 常见问题

### Q1: 向量检索失败如何处理？
**A**: 系统实现三级降级策略：Chroma 向量 → MySQL 向量 → MySQL 全文检索，保证高可用。

### Q2: 如何添加新的 LLM 提供者？
**A**: 实现 `LLMProvider` 接口，在 `application.yml` 中配置即可。

### Q3: 如何扩展自定义 Skill？
**A**: 在 `skills/` 目录下创建新的 Skill 目录，编写 Groovy 脚本和 SKILL.md 配置文件。

### Q4: 如何处理行业特定逻辑？
**A**: 通过 SPI 扩展机制实现 `IndustryTargetExtractor` 接口，在 `application.yml` 中配置即可。
